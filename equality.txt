Equality in C#

First we have value types and ref types

In general the value types compare the actual values
And the ref compare the identity(means two variables have the same reference to tha same object)

What i know, we have ==, Equal with GetHashCode and IEquatable

For {==} => this will use the default behavior unless the type overloads the operator

	- for main  types like, int, bool, char...etc it's fine don't care
	- for built in value types like decimal, datetime, guid... it has also == and it works fine, don't care
	- for ref types, it does reference equality directly
	
For Equal method => it will run the base class method, for ValueType or Object unless the type overrides the method

	- for built in ValueType => int, bool, char, DateTime..etc => it avoids boxing because they implement IEquatable<T>, and also override the Equals and GetHashCode

	- For custom value types like creating a new struct => it will call ValueType.Equals and may be slower / involve boxing depending on the path and field types, so each field will have the correct equality.

	- for ref types => it will run Object.Equals which does reference equality directly

	- if you need to override the method you must also override GetHasCode, mainly GetHasCode it will be used by hash-based structures/algorithms like Dictionary, HashSet, so in this case if x.Equals(y) is trues, they must return the same hash code. 
	
For IEquatable<T> => this give you a method Equals(T other) that doesn't take Object, so you can use it without boxing in general, and in this case you must also override Equals() with calling IEquatable.Equals(), and GetHashCode()

A standard advice => an equatable class should be sealed, because equatable here means that we wil compare between two variables from type X, so the two variables must be from the same type
So if the class is not sealed in this case we can run this base.Equals(derived) or derived.Equals(base)
because we ca write this code Base derived = new Derived(); Base base = new Base()

For EqualityComparer<T>.Default is the generic way to compare two T values using the type’s default equality semantics, usually avoiding unnecessary boxing when a better typed path exists.

Records give you all four at once — Equals, GetHashCode, ==/!=, and IEquatable<T> — all value-based, all consistent with each other. That's the whole reason records are right for DTOs and wrong for entities: an entity's identity is its key, not its contents, and two rows with identical fields are still two different things.
